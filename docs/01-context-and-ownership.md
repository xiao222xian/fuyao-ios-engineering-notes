# 背景、目标与职责边界

## 产品问题

高考志愿辅助产品需要把成绩、位次、地区、科目与院校专业信息连接起来。用户通常不会只执行一次搜索，而是在档案录入、推荐列表、院校详情、自己的志愿表和 AI 问询之间来回切换。后续的生涯规划又增加了资料采集、多轮对话、报告生成与文档下载。

对客户端来说，任务既包括展示内容，也包括保留用户的选择、说明等待原因、恢复既有记录，以及避免在网络异常时把已加载内容全部丢掉。

公开复盘聚焦这些工程问题，不给出录取保证，也不把“冲、稳、保”这样的产品分组当作经过校准的概率模型。

## 工程目标

| 目标 | 具体含义 | 不能据此推导 |
|---|---|---|
| 多端业务一致 | 同一上下文使用相同筛选语义和数据解释 | UI 外观一致就代表结果正确 |
| 页面状态可理解 | 初次加载、空结果、局部失败分别呈现 | 后端成功响应就代表用户完成任务 |
| 跨入口可恢复 | 列表、详情和历史记录指向同一业务实体 | 本地缓存能替代服务器最终状态 |
| 异步任务可追踪 | 对话结束与报告可下载分别处理 | 文本生成结束就代表文件已准备好 |
| 工程可以交接 | 记录做了什么、验证了什么、还差什么 | 存在 Git 提交就代表已上线验收 |

## 系统背景与个人工作

归档包含多个客户端与服务端模块。整体产品提供查询、推荐、AI 交互、报告和账号相关能力。这里的系统边界用于解释 iOS 为什么需要适配某些数据和状态，不用于宣称这些模块都由同一个人开发。

本复盘归纳的 iOS 相关工作包括：

1. 对照既有产品语义，调整查询上下文、批次与科目等参数及字段解码。
2. 处理搜索请求重叠、加载状态和失败后的已有内容保留。
3. 区分专业组聚合选择与子专业选择，改进局部操作反馈及失败恢复。
4. 接入生涯规划的原生界面、流式问询、历史恢复与报告入口。
5. 调整导航、滚动区域和可复用卡片，使多个入口的交互语义一致。
6. 进行局部代码检查、构建尝试与交接记录整理。

服务端推荐算法、模型训练、数据采购、业务运营、支付基础设施与生产运维不被列为个人独立成果。涉及平台能力的文字均采用系统背景视角。

## 复盘方法

本文重新阅读归档中的 iOS 实现及项目交接记录，再用自己的结构和语言总结问题、方案与限制。没有直接公开原交接文档、接口清单、内部协作记录或代码片段。

证据分为四类：源码可见实现、历史执行记录、本次静态推断、未来建议。一个技术点可能同时具有前两类证据，但仍缺少真机和线上证据。

实际归档时，本地工程与公开说明分开保存。公开仓库只包含这份原创文档与概念示意；读者不能用它恢复原商业系统。
