# 开发演进与验证过程

## 不是一次性重写

保存的开发记录呈现出逐步对齐的过程：先处理查询和卡片展示，再处理组级选择语义、搜索并发与输入一致性，随后扩展到生涯规划的连续任务。

下面的阶段按工程问题归纳，不构造精确工时，也不将协作代码全部归给一个作者。

| 阶段 | 主要问题 | 采取的方向 | 证据限制 |
|---|---|---|---|
| 页面和数据对齐 | 相似页面在不同上下文返回不同内容 | 检查环境、批次、科目与字段映射，复用卡片语义 | 源码和历史局部检查；需要同条件真机比对 |
| 选择状态修正 | 子专业选择被父级标记或局部编号影响 | 引入作用域身份，分离孩子状态与组级聚合 | 源码可见；快速连点与跨页并发未重新实测 |
| 查询体验修正 | 重复请求、首屏空态闪现、刷新失败覆盖列表 | 合并触发，区分加载阶段，保留已有内容 | 机制可见；没有公开性能基准 |
| 生涯规划扩展 | 多轮问询、历史恢复、异步报告 | 原生入口、事件接收、状态显示、文档下载与分享 | 有历史局部检查及构建记录；最新流程仍需完整回归 |
| 项目结项 | 完整材料与公开表达混在一起会产生风险 | 私密材料归档与独立原创复盘分离 | 本次核验的是文件与归档完整性，不是线上功能 |

## 历史验证需要按日期解释

部分六月记录描述完整构建在第三方 SDK 签名校验阶段阻塞。这不能归因于某个后来尚未执行到的 Swift 文件，也不能把语法解析通过当作完整构建通过。

较后的七月记录保存了某一阶段模拟器完整构建通过、构建目录锁处理和上传路径受账号权限阻断等情况。它们说明环境与目标版本会影响验证结果，但不应公开真实团队编号、账号或证书信息。

最新功能交接记录中的确认项主要是局部 Swift 语法检查与提交状态；同时留下首页入口、问询、报告下载分享等真机检查待办。因此不能把较早构建通过的证据自动绑定到最新所有功能。

## 分层验证表

| 层级 | 证明什么 | 本复盘可报告的情况 |
|---|---|---|
| 静态阅读 | 实现了哪些分支与状态 | 本次重新阅读了相关 iOS 实现 |
| 语法解析 | 指定源文件能被解析 | 历史交接记录多次记载通过；本次未重跑 |
| 完整构建 | 指定版本、目标和依赖能生成构建产物 | 有历史通过与阻塞记录；本次未重跑 |
| 真机用户流程 | 导航、输入、网络交互与系统分享实际可用 | 历史存在待办，不能宣称全面验收 |
| 线上与平台 | 当前服务、账号、商店发布实际状态 | 此次未连接、未核验 |
| 归档完整性 | 上传内容可独立取回并匹配校验清单 | 结项流程执行过文件大小和 SHA-256 核对 |

归档校验属于材料管理证据，不能支持推荐准确率或 App 稳定性的结论。

## 如果重启，建议怎样做验证

以下是复盘提出的测试设计，不是已执行的测试成绩。

| 测试对象 | 人工构造输入或操作 | 应观察的不变量 |
|---|---|---|
| 搜索调度 | 连续输入、改筛选、加载下一页并迅速切模式 | 不并行重复加载同一列表；展示上下文可解释 |
| 组合身份 | 两个组中使用相同局部编号 | 改一行不会改变另一组的行 |
| 乐观更新 | 请求失败与连续点击交错 | 回滚只影响相应操作，不覆盖更新状态 |
| 区间规范化 | 反向端点、越界端点、缺失边界 | 在合法边界下有序且不越界 |
| 输入来源 | 手填位次与旧估算同时存在 | 提交值来源明确；页面文本与模型一致 |
| 事件流 | 对每种字节分割位置拆开中文和事件分隔符 | 事件内容不丢失、不提前终止 |
| 报告资源 | 生成中、已完成但无文件、文件同步后刷新 | 状态提示与下载能力一致 |
| 页面恢复 | 切换入口、返回、重新打开历史记录 | 不重复创建业务任务，必要上下文保持 |

这类测试可以优先使用离线假服务和虚构数据；只有有明确授权且确有必要时，才连接真实账号和线上环境。
